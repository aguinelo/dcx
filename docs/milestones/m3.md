# M3 — Plano e execução

## Objetivo

Levar o fluxo interativo do contrato aprovado até uma entrega verificada, com plano versionado, executor separado do verifier e parada no gate de merge.

## Escopo

- `planner` transforma contrato e suíte travada em `plan`, sem escrever código.
- O plano cobre todos os critérios, atribui todos os sensores e declara um passo de integração.
- A engine valida o plano contra o contrato e a suíte antes de executar.
- O executor roda em modo `workspace-write` em uma cópia isolada do projeto; o verifier roda em modo `read-only` nessa cópia.
- Sensores visíveis orientam as tentativas; sensores ocultos só rodam na verificação.
- A execução para em `awaiting_merge`; o merge continua sendo decisão humana.
- Só uma execução aprovada aplica os arquivos alterados de volta ao projeto; uma reprovação preserva a cópia para inspeção.
- Plano, step reports, resultados de sensores, veredito e relatório de entrega ficam em `.harness/runs/<run_id>/`.

## Entregue nesta fatia

- `Plan::validate_for`: cobertura de critérios e sensores, ids únicos, dependências conhecidas, integração completa e grafo acíclico.
- `CodexCliPlanner` e `prompts/planner.md` para gerar o plano em modo somente leitura.
- `RunCoordinator::stop_at_merge` permite encerrar em `awaiting_merge` sem marcar `done`.
- O fluxo interativo copia o projeto para `HARNESS_STATE_DIR/runs/<run_id>/workspace`, executa o passo de integração nessa cópia, salva `plan.json`, `step_reports.json`, `sensor_results.json`, `verdict.json` e `delivery_report.json`, e atualiza `run.json`.
- Em caso de aprovação, apenas os caminhos alterados são copiados de volta ao projeto; em caso de reprovação, o projeto não é tocado.
- Os testes de integração usam um Codex falso que implementa o marcador do executor; os sensores só passam depois desse marcador existir.

## Pendente

- Planos multi-passo: hoje o fluxo interativo exige um único passo de integração.
- Aplicação atômica das mudanças e um comando de aplicação/rollback; hoje a cópia aprovada é aplicada arquivo a arquivo.
- Retomada de execução e limpeza do diretório de estado.
- Sandbox de sistema operacional para os sensores.
- Contestação de sensor e reautoria parcial.

## Validação

- `cargo test --workspace` cobre validação de plano, gate de merge e o fluxo interativo completo com Codex falso.
- `cargo run -p harness-cli -- run --demo` continua exercitando o caminho determinístico sem modelo.
- `cargo run -p harness-cli -- run --request "..."` gera sensores, plano, execução e relatório, parando em `awaiting_merge`.
