# M4 — Prova adversarial

## Objetivo

Demonstrar que sensores ocultos reprovam um atalho que só cobre os exemplos visíveis, e preparar a disputa de sensor.

## Entregue

- `examples/job-02`: contrato, suíte com três sensores visíveis e dois ocultos, e README.
- `harness run --job-02`: plano de dois passos; o passo visível passa com um dicionário de comparação exata e a integração é reprovada pelos ocultos.
- `SensorSuite::for_step`: cada passo executa somente os sensores que lhe foram atribuídos, preservando o isolamento dos ocultos.
- `SensorDispute`, `DisputeDecision` e `resolve_sensor_dispute`: uma disputa aceita troca apenas o sensor contestado e mantém os demais.
- `sanitize_verdict`: remove ids, checks e notas de sensores ocultos do veredito antes de realimentar o executor.
- O veredito combinado de planos multi-passo deduplica critérios e issues.

## Validação

- `cargo run -q -p harness-cli -- run --job-02` imprime passo visível aprovado e integração reprovada.
- Testes cobrem `for_step`, disputa e saneamento.
